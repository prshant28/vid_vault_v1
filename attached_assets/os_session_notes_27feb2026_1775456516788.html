§02

Introduction — Why Operating Systems?

Users want applications to run smoothly without worrying about hardware details. If applications accessed hardware directly, it would cause security vulnerabilities and resource management chaos. The OS acts as an intermediary layer between user applications and hardware, managing six core responsibilities:

⚙️ Process Management Managing running programs, scheduling CPU time
🧠 Memory Management Allocating & tracking RAM usage across processes
🖨️ I/O Management Handling input/output devices & requests
📁 File Management Organizing & protecting stored data
🔒 Security Management Protecting system resources from unauthorized access
🌐 Network Management Handling network communications & protocols
§03

Von Neumann Architecture

COMPONENT 1 CPU Executes instructions fetched from memory. Contains cores for parallel processing.
COMPONENT 2 Memory (RAM) Stores active process instructions & data. Managed entirely by the OS.
COMPONENT 3 I/O Devices Screen, printer, USB, keyboard — communicate via I/O requests & interrupts.
🔑 Key Concept — DMA
  • DMA (Direct Memory Access) is a dedicated processor that enables data to transfer directly between I/O devices and memory without CPU involvement
  • Frees the CPU from managing every byte of data movement
  • Example: Copying a file from USB drive goes through DMA, not the main CPU
  • Interrupts notify the CPU once DMA transfer is complete
🖥️ CPU vs GPU
  • CPUs: 4–16 cores — general purpose workloads
  • GPUs: Thousands of cores — matrix operations
  • GPUs are optimized for AI/ML matrix multiplication workloads
  • More cores = more complex OS management across memory, processes & I/O
  • CPUs handle sequential logic; GPUs handle massively parallel computation

User Mode vs Kernel Mode

👤 USER MODE MODE BIT = 0
  • Where regular application code runs
  • No direct access to hardware
  • Limited privileges — cannot write to system memory
  • Examples: web browser, Python script, games
  • Any hardware access triggers a system call
🔧 KERNEL MODE MODE BIT = 1
  • Where OS executes system calls on behalf of apps
  • Full hardware access — trusted execution
  • Transition via trap bit switching 0 → 1
  • Examples: print, file open, memory allocation
  • Returns to user mode after system call completes
📌 How the Switch Works
When an application needs hardware access (e.g., printing to screen), a system call is issued. The hardware trap mechanism automatically changes the mode bit from 0 → 1, switching execution from user mode to kernel mode. After the OS handles the request, the mode bit returns to 0 and control goes back to the application.
§05

System Calls — When & Why They Occur

System Call When It Triggers What the OS Does Tag
read() Reading data from a file or input stream OS fetches data from storage/I/O and copies to process memory I/O
write() Writing data to a file or output stream OS sends data to disk or output device via I/O subsystem I/O
print() Displaying output on screen OS communicates with display device driver to render output I/O
open() Opening a file from disk OS locates file in filesystem, creates file descriptor for process File
fork() / exec() Spawning a new process OS allocates PCB, memory space, and schedules new process Process
malloc() Requesting heap memory allocation OS memory manager assigns a block of RAM to the calling process Memory
§06

Program vs Process

📄 Program — Passive Entity
  • A file stored on hard drive or SSD (secondary storage)
  • Examples: .py, .exe, .jar files
  • Does not consume CPU time or RAM on its own
  • Static — just bytes sitting on disk until executed
  • One program can create multiple processes
⚡ Process — Active Entity
  • A program in execution, loaded into RAM (main memory)
  • Has its own memory space: code, stack, heap, data segments
  • Actively uses CPU time and memory resources
  • OS tracks it via a Process Control Block (PCB)
  • State can be: Running, Ready, Waiting, Terminated

System calls are the only safe gateway for applications to interact with hardware. Every print, file read, network request, or memory allocation goes through a system call — this is how the OS maintains control and security.

Deadlock — Four Necessary Conditions

A deadlock occurs when two or more processes are blocked indefinitely, each waiting for a resource held by the other. All four conditions must hold simultaneously for deadlock to occur.

CONDITION 1 Mutual Exclusion At least one resource must be non-shareable — only one process can use it at a time
CONDITION 2 Hold & Wait A process holds one resource and waits to acquire additional resources held by others
CONDITION 3 No Preemption Resources cannot be forcibly taken from a process — only released voluntarily
CONDITION 4 Circular Wait A closed chain of processes exists where each waits for a resource held by the next
💡 Prevention Strategy
One technique: require processes to request all needed resources upfront before starting. This eliminates the Hold & Wait condition. Breaking any one of the four conditions is sufficient to prevent deadlock.
§08

Inter-Process Communication (IPC)

📦 Shared Memory
  • Processes share a common memory region
  • Works like a "common room" — processes dump and read updated values
  • Faster — no kernel involvement after setup
  • Requires synchronization to avoid race conditions
  • Best for: high-speed, high-volume data exchange
📨 Message Passing
  • Processes communicate by sending/receiving messages
  • OS kernel mediates every message exchange
  • Safer — no shared memory, no race conditions
  • Slightly slower due to kernel involvement
  • Best for: distributed systems, inter-machine communication
§09

Memory Hierarchy

Cache Closest to the CPU. Stores frequently used data for near-instant access. Automatically managed by hardware. L1/L2/L3 levels exist — L1 fastest, L3 largest. Fastest ⚡⚡⚡
RAM (Main Memory) Where active processes live. Managed by the OS. Volatile — data lost on power-off. Programs must be loaded here from disk before execution. Fast ⚡⚡
Hard Drive / SSD Secondary storage where programs (.py, .exe) are permanently stored. Non-volatile. OS reads from here when launching a program into RAM. Slower ⚡
§10

The Kernel — Heart of the OS

🖥️ What Is the Kernel?
  • The main OS file loaded first when the system starts (boot process)
  • Contains the core OS code: process scheduler, memory manager, device drivers
  • Only kernel files are loaded into RAM initially — to conserve memory
  • Acts as the bridge between hardware and all software
  • Runs permanently in memory while the system is on
