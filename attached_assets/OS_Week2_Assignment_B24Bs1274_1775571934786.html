Task 2 — Written Questions: Why are Zombie Processes Dangerous?

Q1. What resource does a zombie process consume, and why is this dangerous in long-running systems?
A zombie process consumes a slot in the kernel's process table even though it has finished executing and holds no CPU, memory, or open files. Each slot is identified by a unique PID, and Linux has a finite PID limit (typically ~32,768). When a buggy parent continuously forks children without calling wait(), zombie entries accumulate indefinitely. Once all PID slots are exhausted, the OS cannot create any new process — including critical system daemons — potentially causing a complete system freeze without a reboot.
Q2. Can a zombie process be killed with the kill command? What must happen to properly remove it?
No — a zombie cannot be killed with any signal, including SIGKILL, because it is already dead. It has no running code to receive or handle signals. The only proper way to remove a zombie is for its parent to call wait() or waitpid(), which tells the kernel to collect the exit status and release the PID slot. If the parent itself is killed, the zombie is re-parented to init, which periodically calls wait() to clean up children. The real fix is to correct the parent's code — typically by catching the SIGCHLD signal and calling wait() inside the handler.
Q3. What is the difference between a zombie and an orphan in terms of danger to the system?
A zombie is a dead process whose exit status has not been collected — it holds a PID slot but consumes no CPU or memory, yet can cause PID exhaustion if they accumulate. An orphan is a live process whose parent has died — the kernel automatically re-parents it to init (PID 1), which properly calls wait() when the orphan eventually exits, preventing a zombie from forming. Therefore, orphans are mostly benign (they may run unintended background work), whereas uncollected zombies represent a resource leak that directly threatens system stability.
QUICK SUMMARY — Zombie vs Orphan ZOMBIE = Dead child + parent never called wait() → PID slot stuck → DANGEROUS (PID exhaustion) ORPHAN = Living child + parent died early → re-parented to init → init calls wait() → SAFE ✓ FIX = Parent must call wait() / handle SIGCHLD signal → zombie never forms
